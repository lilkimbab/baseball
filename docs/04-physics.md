# 04. 물리

공의 비행·충돌·바운드, 선수의 운동 모델, Godot 물리와의 관계. 수식과 상수는 [prototypes/physics-check](../prototypes/physics-check/check.mjs)로 검증했고, Godot 구현 가능성은 [prototypes/godot-spike](../prototypes/godot-spike/)로 확인했다.

## 1. 원칙

1. **공은 엔진 강체가 아니다.** `BallSim`이 위치·속도·회전을 직접 적분한다. 범용 물리 엔진에는 항력과 매그너스 힘이 없고, 엔진 강체는 "미리 끝까지 돌려 보기"가 안 된다
2. **구장과의 충돌 판정만 엔진에 묻는다.** 매 스텝 공이 이동할 구간을 Jolt의 구 스윕 질의(`cast_motion`)로 검사하고, 닿으면 반발은 직접 계산한다
3. **예측과 실제가 같은 코드다.** 타구가 맞는 순간 같은 `BallSim`으로 낙하 지점까지 한 프레임 안에 계산한다. 수비 AI, 낙하 지점 표시, 홈런 판정 카메라가 이 예측을 쓴다
4. **배트-공 충돌은 해석식이다.** 배트를 물리 물체로 휘두르지 않는다
5. **선수는 운동 모델로 움직인다.** 캡슐 강체로 밀고 당기지 않는다. 위치는 가속·최고 속도 모델이 정하고 애니메이션이 따라간다
6. 엔진 강체(Jolt)는 꾸미는 용도로만 쓴다. 놓친 배트, 날아간 헬멧, 죽은 공

## 2. 좌표계와 단위

`core/` 안에서는 **필드 좌표**를 쓴다. SI 단위(m, s, kg, rad).

| 축 | 방향 |
|---|---|
| +x | 1루 쪽 (포수가 볼 때 오른쪽) |
| +y | 홈에서 중견수 쪽 |
| +z | 위 |
| 원점 | 홈플레이트 뒤 꼭짓점, 지면 |

Godot 월드 좌표(Y가 위, −Z가 앞)로는 씬 경계에서만 바꾼다.

```gdscript
static func to_world(f: Vector3) -> Vector3:
    return Vector3(f.x, f.z, -f.y)

static func to_field(w: Vector3) -> Vector3:
    return Vector3(w.x, -w.z, w.y)
```

`Vector3`는 단정밀도다. 구장 규모(150m)에서 정밀도는 약 0.01mm로 충분하다. 시간 누적은 배정밀도 `float`로 한다.

## 4. 공의 비행

### 4.1 상수

| 기호 | 값 | 설명 |
|---|---|---|
| m | 0.145 kg | 공 질량 |
| r | 0.0366 m | 공 반지름 |
| A | πr² = 4.21×10⁻³ m² | 단면적 |
| ρ | 1.20 kg/m³ | 공기 밀도 (해수면, 20℃) |
| K | ρA / 2m = 0.01742 m⁻¹ | |
| g | 9.81 m/s² | |

### 4.2 힘

```
a = g + a_drag + a_magnus

a_drag   = −K · Cd · |v| · v
a_magnus =  K · Cl · |v|² · (ω⊥ × v) / |ω⊥ × v|

Cd = 0.33 + 0.02 · (회전수[rpm] / 1000)
S  = r · |ω⊥| / |v|                      회전 계수
Cl = 1.05 · S / (0.583 + 2.333 · S)
ω(t) = ω₀ · exp(−t / 25)                 회전 감쇠
```

- `ω⊥`는 회전 벡터 중 진행 방향에 수직인 성분이다. 진행 방향과 나란한 성분(자이로 회전)은 휘는 힘을 만들지 않는다. 슬라이더가 회전수에 비해 덜 휘는 이유다
- 매그너스 힘의 방향은 `ω × v`다. +y로 날아가는 타구의 백스핀은 ω = +x, 힘은 +z(위)
- 계수는 야구공 풍동·추적 연구에서 쓰는 형태의 근사이며, 4.3의 목표에 맞춰 조정한 값이다
- 바람은 `v` 대신 `v − v_wind`를 넣으면 된다. 구장별 옵션

### 4.3 적분

- RK4, 고정 간격 **1/240초**. 투구 한 개가 약 105스텝, 뜬공 한 개가 약 1,250스텝
- GDScript로 스텝당 1.64μs(이 PC 기준). 공 하나를 실시간의 2,500배로 돌릴 수 있다
- 기준 계산(배정밀도 JS)과 GDScript 구현의 차이: 120m 비행에서 4cm

## 5. 투구

### 5.1 릴리스 상태 만들기

입력: 구종, 구속, 회전수, 회전 효율, 회전축 기울기, 릴리스 지점, 목표 지점.

1. 릴리스 지점은 투수의 키·팔 각도·익스텐션으로 정한다. 우완 오버핸드 기준 약 (−0.55, 16.76, 1.80). 좌완은 x 부호 반대
2. 회전 벡터 = 유효 성분(진행 방향에 수직, 기울기로 방향 결정) × 효율 + 자이로 성분(진행 방향) × √(1 − 효율²)
3. **조준 해법**: 목표 지점을 향해 쏘고, 도달 지점과 목표의 차이만큼 조준점을 옮겨 다시 쏜다. 3~6회 반복하면 오차 0.01cm 이하. 투수는 "휘어서 그 지점에 도달하도록" 던지는 것이다
4. 실행 오차를 더한다(5.2)

### 5.2 실행 오차

홈플레이트 평면에서의 빗나감(cm)은 2차원 정규분포다.

```
σ = lerp(34, 12, 제구/100) × 구종 숙련 보정 × (1 + 0.5 × 피로 초과분) × 입력 품질 보정
```

- 입력 품질: 사람의 게이지 정확도 또는 AI의 추첨. 완벽이면 ×0.5, 최악이면 ×2.5
- 방향 편향: 릴리스가 빠르면 높은 팔 쪽, 늦으면 낮은 글러브 쪽으로 치우친다
- 전력투구는 구속 +2km/h, σ ×1.25, 체력 소모 1.5배
- 오차가 타석 쪽으로 크면 몸에 맞는 공, 포수가 못 닿는 범위면 폭투 판정 대상

### 5.3 구종 카탈로그 (우완, 초기값)

무브먼트는 회전이 없을 때 대비 릴리스에서 플레이트까지의 편차다. 가로는 음수가 팔 쪽(3루 쪽), 양수가 글러브 쪽. 기준 계산 결과다.

|---|---|---|---|---|---|---|---|---|
| 포심 | 145 | 2300 | 0.90 | −12 | 0.428 | 131.2 | −9 | +46 |
| 투심 | 142 | 2150 | 0.88 | −50 | 0.437 | 128.6 | −34 | +29 |
| 커터 | 138 | 2350 | 0.50 | +25 | 0.450 | 124.9 | +16 | +30 |
| 슬라이더 | 132 | 2400 | 0.35 | +75 | 0.471 | 119.5 | +29 | +7 |
| 스위퍼 | 128 | 2600 | 0.60 | +85 | 0.486 | 115.9 | +44 | +3 |
| 커브 | 120 | 2500 | 0.75 | +160 | 0.519 | 108.8 | +20 | −47 |
| 체인지업 | 130 | 1750 | 0.88 | −60 | 0.477 | 118.2 | −36 | +20 |
| 스플리터 | 132 | 1300 | 0.35 | −40 | 0.469 | 120.3 | −10 | +13 |

- 기울기는 포수가 볼 때 매그너스 힘의 방향. 0°가 위, +90°가 1루 쪽
- 선수별 구종은 이 기본값에 구속 차이, 무브먼트 등급(회전수·효율 배율), 팔 각도(기울기 회전)를 적용한다
- 사이드암·언더핸드는 릴리스 지점이 낮고 기울기 전체가 회전한다
- 진화 구종(서클 체인지업, 파워 커브 등)은 같은 계열의 파라미터 변형으로 정의한다
- 포크볼·너클볼·팜볼은 저회전 계열로 추가한다. 너클볼은 회전이 거의 없어 궤적에 저주파 무작위 힘을 더한다

## 7. 배트-공 충돌

### 7.1 접촉 파라미터

입력(사람 또는 AI)은 세 개의 접촉 파라미터로 바뀐다. 변환 규칙은 [05](05-controls-camera-ui.md#22-타격)에 있다.

| 파라미터 | 의미 | 원인 |
|---|---|---|
| ψ (배트 수평각) | 임팩트 순간 배트가 얼마나 돌아가 있나. 양수면 앞에서 맞음(당겨치기) | 타이밍 |
| d (상하 어긋남) | 공 중심이 배트 축보다 얼마나 위에 있나 | 상하 조준, 구종 인식 |
| s (배트 위 위치) | 배트 끝에서 접촉점까지 거리 | 좌우 조준, 코스 |

그 밖의 입력: 배트 속도(파워 능력치와 스윙 종류), 어택 앵글(스윙 궤도의 상향각, 기본 +8°).

### 7.2 계산

```
R = r_공 + r_배트 = 0.0366 + 0.033
|d| ≥ R 이면 헛스윙

n = 배트 축에서 공 중심을 향하는 단위 벡터 (sin θ = d / R 만큼 위로 기울어짐)
v_rel = v_공 − v_배트
v_n = v_rel · n                      (음수: 접근 중)
v_t = v_rel − v_n · n                접선 성분
u = v_t + c_mem · (ω_공 × (−r · n))   접촉점의 미끄럼 속도

v'_rel = −e_A · v_n · n + v_t − (2/7) · k_f · u
v_타구 = v_배트 + v'_rel
ω_타구 = c_mem · ω_공 + (5/7) · k_f · (n × u) / r
```

| 상수 | 값 | 의미 |
|---|---|---|
| e_A | 0.20 (스윗 스폿) | 충돌 효율. 정면 충돌이면 `타구 속도 = e_A × 투구 속도 + (1 + e_A) × 배트 속도` |
| e_A(s) | 스윗 스폿(끝에서 15cm)에서 최대, 멀어지면 `1 − ((s − 0.15) / 0.22)²`로 감소. 최소 −0.1 | 먹힌 타구, 배트 끝 타구 |
| k_f | 0.55 | 접선 방향 마찰 전달 비율 |
| c_mem | 0.1 | 들어온 공의 회전이 남는 비율. 타구 회전은 투구 회전과 거의 무관하다 |
| r_배트 | 0.033m | 배럴 반지름 |

배트 속도(스윗 스폿 기준): `lerp(98, 124, 파워/100)` km/h. 컨택 스윙 ×0.93, 파워 스윙 ×1.06.

## 8. 바운드, 구르기, 벽

### 8.1 반발 모델

질량이 큰 면에 구가 부딪힐 때의 충격량 모델. 마찰은 쿨롱 한계까지만 전달된다.

```
v_n = v · n            (음수일 때만 처리)
u   = v_t + ω × (−r · n)
j_n = −(1 + e) · v_n
j_t = min((2/7) · |u|, μ · j_n)

v' = v_t − e · v_n · n − j_t · û
ω' = ω + 2.5 · (j_t / r) · (n × û)
```

- 톱스핀이 걸린 땅볼은 바운드 후 앞으로 뻗고, 백스핀이 걸린 타구는 죽는다. 식에서 자연스럽게 나온다
- 바운드 후 수직 속도가 0.5m/s 미만이면 구르기 상태로 바꾼다. 구르기는 면별 감속도로 줄어든다

### 8.2 면별 상수 (초기값)

| 면 | 반발 e | 마찰 μ | 구름 감속 m/s² |
|---|---|---|---|
| 천연 잔디 | 0.45 | 0.55 | 3.0 |
| 내야 흙 | 0.50 | 0.50 | 2.2 |
| 인조 잔디 | 0.55 | 0.45 | 1.8 |
| 경고 트랙 | 0.45 | 0.55 | 2.5 |
| 펜스 패드 | 0.35 | 0.50 | |
| 단단한 벽·전광판 | 0.55 | 0.40 | |
| 그물 | 0.05 | 0.80 | |
| 베이스 | 0.40 | 0.50 | |

면 종류는 콜라이더의 메타데이터(`surface`)로 읽는다. 지면은 콜라이더 하나이고 위치로 종류를 정한다(`FieldSurface.at(x, y)`).

땅볼 속도 목표: 타구 속도 150km/h, 발사각 −5°가 유격수 깊이(40m)에 **1.15~1.30초**에 도달. 현재 상수로 1.31초다. 구현 단계에서 e와 μ를 조정해 맞춘다.

### 8.3 충돌 제공자

```gdscript
class_name CollisionProvider
extends RefCounted

## from에서 to로 반지름 r의 구를 이동시킬 때 처음 닿는 지점. 없으면 null.
func sweep(from: Vector3, to: Vector3, r: float) -> Hit:
    return null
```

| 구현 | 쓰는 곳 | 내용 |
|---|---|---|
| `AnalyticField` | 헤드리스 테스트, 배치 시뮬레이션 | 지면 평면 + 펜스 폴리라인(방위각별 거리와 높이) + 백스톱. 수식으로 계산 |
| `SceneSpace` | 경기 씬 | `PhysicsDirectSpaceState3D.cast_motion()`으로 구장의 실제 콜라이더에 질의. 더그아웃, 난간, 광고판, 폴대까지 반영 |

두 구현은 같은 구장 정의에서 만들어지므로 주요 결과(낙하 지점, 펜스 넘김)가 일치해야 한다. 이것도 테스트 항목이다.

## 9. 송구

송구도 같은 `BallSim`을 쓴다.

- 송구 속도: 내야수 `lerp(112, 146, 송구력/100)`, 외야수 `lerp(120, 156, 송구력/100)` km/h. 급한 송구나 불안정한 자세면 감속
- 회전: 백스핀 1,400~2,000rpm
- 발사각은 조준 해법으로 구한다. 목표는 받는 야수의 가슴 높이
- 오차: 송구 정확도와 입력 품질로 정해지는 원뿔. 크게 빗나가면 악송구
- 공을 빼는 시간: `lerp(0.95, 0.55, 포구/100)`초. 달려오며 던지기, 점프 스로는 별도 값
- 원바운드 송구: 거리 55m 이상이면 낮게 던져 한 번 튀기는 편이 빠르다. AI가 비교해서 고른다

## 10. 선수 운동 모델

| 항목 | 모델 |
|---|---|
| 최고 속도 | `lerp(7.2, 9.3, 주력/100)` m/s |
| 가속 | `v(t) = v_max · (1 − exp(−t / 1.0))`. 타석에서 1루까지 4.0~4.7초 |
| 수비 반응 | 타구 후 `lerp(0.45, 0.22, 수비 범위/100)`초 뒤 출발. 첫걸음 방향 오류 확률은 포구 능력치로 |
| 수비 경로 | 직선 대비 효율 `lerp(0.90, 0.99, 수비 범위/100)` |
| 포구 범위 | 선 자세 1.0m, 달리며 1.4m, 다이빙 2.4m(성공 후 송구 지연 +0.9초), 점프 높이 3.0~3.3m |
| 포구 성공 | 여유 시간 0.25초 이상이면 평범한 타구(실책률만), 0~0.25초는 러닝 캐치(90% → 60%), −0.15~0초는 다이빙(50% → 10%) |
| 리드 | 1루 3.0~4.2m. 클수록 견제사 위험 |
| 도루 스타트 | 투수 동작 시작 후 `lerp(0.30, 0.12, 주루/100)`초 |
| 슬라이딩 | 베이스 3.5m 전부터. 태그를 피하는 판정 보너스 |
| 포수 팝 타임 | `lerp(2.15, 1.85, 송구력/100)`초 (포구에서 2루 도달까지) |
| 투수 퀵 모션 | 1.20~1.50초 (동작 시작에서 포수 미트까지) |

액터의 위치는 이 모델이 정하고, 애니메이션은 속도에 맞는 이동 클립을 블렌딩해 따라간다. 발 미끄러짐은 재생 속도 보정으로 줄인다.

## 11. Godot 통합

| 항목 | 설정 |
|---|---|
| 물리 엔진 | Jolt Physics (`physics/3d/physics_engine`) |
| 물리 틱 | 120Hz. 공은 틱당 2스텝(240Hz) |
| 공 | `BallSim`(RefCounted). 씬의 `BallActor`(Node3D)는 매 틱 위치와 회전을 읽어 표시만 한다 |
| 구장 콜라이더 | `StaticBody3D` + 메타데이터 `surface`. 구장 생성기가 메시와 함께 만든다 |
| 충돌 질의 | `_physics_process` 안에서 `direct_space_state.cast_motion()` → 닿으면 `get_rest_info()`로 법선과 콜라이더 |
| 궤적 예측 | 타구 순간 같은 틱 안에서 끝까지 시뮬레이션. 뜬공 1,974회 질의에 4.2ms |
| 선수 | 물리 바디 없음. 포구·태그는 거리 판정 |
| 꾸밈용 강체 | 놓친 배트, 헬멧 등은 `RigidBody3D`. 경기 결과에 영향 없음 |
| 화면 보간 | 물리 보간을 켜거나, 120Hz 틱이면 생략 가능 |
